# Modern UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the WinForms window with a WPF-UI status window and tray popup, driven by the work schedule from step 1.

**Architecture:** All state rules live in one UI-free, unit-tested class, `Logic/MoverController.cs`. It tracks whether the app *wants* to run and an optional saved "paused until" time. The WPF window and tray popup only display `MoverController.GetStatus(now)` and forward clicks. Timers and Windows events (lock, sleep, display) live in the window and call into the controller with `DateTime.Now`. The existing movement code (`AutomaticMouseMover`, `WinHelper/*`) is reused unchanged.

**Tech Stack:** .NET 8 (`net8.0-windows`), WPF + WinForms (both enabled), NuGet `WPF-UI` 4.3.0 and `WPF-UI.Tray` 4.3.0, xUnit tests in `AutoMouseMover.Tests`.

**Spec:** `docs/superpowers/specs/2026-10-20-modern-ui-design.md`

## Global Constraints

- Target `net8.0-windows`, with both `<UseWPF>true</UseWPF>` and `<UseWindowsForms>true</UseWindowsForms>` (`AutomaticMouseMover` uses `System.Windows.Forms.Screen`).
- `WPF-UI` and `WPF-UI.Tray` pinned to `4.3.0`. No other new packages.
- Single-file self-contained publish must keep working: `dotnet publish AutoMouseMover/AutoMouseMover.csproj -c Release -r win-x64 --self-contained -p:PublishSingleFile=true`.
- Code style: `m` prefix on fields, `c` prefix on parameters, `#region` blocks, a one-line comment above every method, enum names `eName` with UPPER_CASE members.
- Every UI string exists in both `Properties/lang_en.resx` and `Properties/lang_it.resx`, read through the existing `ResourceManager` pattern (`AutoMouseMover.Properties.lang_<culture>`). No strings hard-coded in XAML.
- Movement limits: interval 2-30 s (default 5), distance 1-200 px (default 5).
- Schedule defaults: off, 09:00-17:00, Monday to Friday.
- `dotnet` here means `& "$env:LOCALAPPDATA\Microsoft\dotnet\dotnet.exe"`. The owner's plain `dotnet` resolves to a runtime-only install.
- **No commits without the owner's go-ahead.** Each task ends with a checkpoint: show the diff and the test output, then wait.
- The owner is learning. After each task, explain what changed, why, and how to verify it, before starting the next.

### Task 2: MoverController (state rules)

**Files:**
- Create: `AutoMouseMover/Logic/MoverController.cs`
- Test: `AutoMouseMover.Tests/MoverControllerTests.cs`

**Interfaces:**
- Consumes: Task 1 `WorkSchedule` (all methods).
- Produces:

```csharp
enum eMoverState { ACTIVE, PAUSED, OUTSIDE_HOURS }

class MoverStatus
{
    public MoverStatus(eMoverState cState, DateTime? cUntil);
    public eMoverState State { get; }
    public DateTime? Until { get; }   // null when there is no time to show
}

class MoverController
{
    public event EventHandler StateChanged;          // raised whenever IsRunning, PausedUntil or Schedule may have changed
    public WorkSchedule Schedule { get; }            // null = schedule off
    public DateTime? PausedUntil { get; }            // saved by the caller; DateTime.MaxValue = until Resume
    public bool IsRunning(DateTime cNow);            // wants to run AND not paused AND not locked
    public void Launch(WorkSchedule cSchedule, DateTime? cSavedPausedUntil, bool cAutoStart, DateTime cNow);
    public void SetSchedule(WorkSchedule cSchedule, DateTime cNow);
    public void Resume(DateTime cNow);
    public void Pause(DateTime cNow);
    public void PauseFor(TimeSpan cDuration, DateTime cNow);
    public void PauseUntilTomorrow(DateTime cNow);
    public void Tick(DateTime cNow);
    public void SetLocked(bool cLocked, DateTime cNow);  // used for both lock/unlock and suspend/resume
    public MoverStatus GetStatus(DateTime cNow);
}
```

The rules (from the spec, "Decisions after review"):
- `mWantRunning`: set true by a schedule `START`, by `Resume`, and by `Launch` when the schedule is off and `cAutoStart` is true. Set false by a schedule `STOP`. `SetSchedule` sets it to `cSchedule.IsWorkingTime(cNow)` (after priming with one `CheckTransition`); a null schedule leaves it as it is.
- `Launch` with a schedule calls `Tick(cNow)`, so a start inside hours runs. A saved pause that has already ended (`<= cNow`) is dropped.
- `Pause`: `PausedUntil = Schedule == null ? DateTime.MaxValue : Schedule.GetNextStart(cNow)`. `PauseFor`: `cNow + cDuration`. `PauseUntilTomorrow`: `Schedule.GetStartOnNextWorkDay(cNow)`. It throws `InvalidOperationException` when the schedule is off.
- `Resume` clears `PausedUntil` and sets `mWantRunning = true`.
- `Tick`: while locked, do nothing. Otherwise apply `Schedule.CheckTransition(cNow)`, then clear `PausedUntil` if `cNow >= PausedUntil`.
- `SetLocked(false, now)` calls `Tick(now)` after unlocking.
- `GetStatus`: paused → `PAUSED`, with `Until = PausedUntil` (null if `MaxValue`). Running → `ACTIVE`, with `Until = GetEndToday(now)` only if the schedule is on and `IsWorkingTime(now)`. Not wanting to run with the schedule on → `OUTSIDE_HOURS`, with `Until = GetNextStart(now)` (null if `MaxValue`). Not wanting to run with the schedule off → `PAUSED`, `Until = null`.
